## 二、过程记录

### 记录 1：最小程序（AI 编程初体验）

**阶段**：AI 初体验
**我的提示词（原话）**：

```
用 Python 写一个最小的命令行程序，运行后输出：Hello, AI 编程！
```

**AI 生成结果**（`hello_ai.py`）：

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""实验一 · AI 编程初体验：最小程序"""


def main() -> None:
    print("Hello, AI 编程！")


if __name__ == "__main__":
    main()
```

**本地运行验证**：

```
$ python --version
Python 3.13.14

$ python hello_ai.py
Hello, AI 编程！
$ echo $?
0
```

**人工校验与微调**：
- 阅读代码：逻辑正确，`main()` 封装 + `if __name__ == "__main__"` 是标准写法，无冗余。
- 验证：实际运行输出与预期完全一致，退出码 0（无报错）。
- 微调：**无需修改**。仅为可读性补了中文注释（非 AI 生成部分），逻辑一行未动。

**结论**：完整体验了「描述需求 → AI 生成代码 → 本地运行验证 → 微调」四步。

### 记录 2：示例项目 LingChat 的环境与运行

**阶段**：项目创建与运行

**背景**：课程给定的"签到系统"示例改用 LingChat（课程允许自行寻找示例代码）。
它是一个 Tauri 2 桌面应用，前端 Vue 3 + 后端 Rust，依赖链比签到系统长得多。

**我的提示词（原话）**：

```
我想在本机跑起 LingChat 这个项目，应该怎么装环境和启动？
它的仓库是 https://github.com/SlimeBoyOwO/LingChat
```

**AI 生成的步骤**：

```bash
git clone https://github.com/SlimeBoyOwO/LingChat.git
cd LingChat
git checkout dc8e49eb          # 固定到实验所用的版本
pnpm install                   # 前端依赖
pnpm tauri dev                 # 开发模式启动完整应用
```

**遇到的实际问题与解决**：

| # | 报错 / 现象 | AI 给出的排查方向 | 最终解决 |
| --- | --- | --- | --- |
| 1 | `pnpm` 未安装 / 版本不符 | 确认 Node.js ≥ 20，用 corepack 启用 pnpm | `corepack enable pnpm` |
| 2 | Rust 工具链缺失，`cargo` 命令找不到 | 检查是否装了 rustup 及 MSVC 生成工具 | 安装 Rust 工具链后 `cargo --version` 通过 |
| 3 | 首次编译耗时很长（Rust 依赖多） | 说明 Tauri 首次编译需构建全部 crate，属正常 | 等待首次编译完成，后续增量编译变快 |
| 4 | 打包产物找不到 | 指出产物在 `src-tauri/target/release/bundle/` | 在该目录找到安装程序 |

**人工校验**：
- AI 给的命令逐条在本机执行过，报错也按它给的排查方向逐个解决；
- 最终应用能正常启动、界面正常显示（见报告正文的运行截图）。

## 三、AI 使用反思

**AI 帮上忙的地方**：
- 环境依赖多、报错信息陌生的场景（Rust / Tauri 工具链），AI 能快速给出排查方向，省去大量搜索时间；
- 格式化文档、整理提交计划这类"结构活"，AI 一次就能给出可用的骨架。

**AI 不可靠、必须人工把关的地方**：
- AI 给出的环境步骤是**通用方案**，与本机实际状态并不总对得上（例如它默认已有 pnpm），
  照抄会卡住，必须自己执行、看报错、再回头纠正；
- AI 无法替你确认"程序真的跑起来了"——**运行验证只能自己看**；
- 本次 AI 给出的最小程序虽然一次就对，但"对"是我运行确认的，不是它声称的。

**结论**：符合实验要求里的定位——**人主导、AI 辅助**。AI 负责提速，正确性由人负责。
